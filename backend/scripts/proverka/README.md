# Проверки

Проверки, които доказват, че поправките по сигурността работят и че нищо не
е счупено. Пускат се на всяка машина — няма твърди пътища.

## Всичко наведнъж

```bash
node backend/scripts/proverka/pusni-vsichko.mjs
```

## Какво е нужно преди това

```bash
# 1. база
docker compose up -d db        # или локален PostgreSQL

# 2. миграции (ако базата е нова)
psql -f backend/src/db/schema.sql
psql -f backend/src/db/migrations/011_lipsvashti_tablici.sql   # и останалите
psql -f backend/src/db/migrations/012_sesii.sql
psql -f backend/src/db/migrations/013_ustrojstva_i_signali.sql

# 3. сървър
cd backend && npm ci && npm run dev

# 4. сглобен сайт (за проверките в браузър)
cd site && npm ci && npm run build
```

## Поотделно

| Скрипт | Какво проверява | Нужно |
|---|---|---|
| `01-sigurnost.mjs` | фалшив токен, изтичане на грешки, заглавки, лимит на опитите, SQL товари | сървър |
| `02-marshruti.mjs` | обхожда всеки GET маршрут и търси 500-ки | сървър + база |
| `03-xss.mjs` | подава в истински браузър товарите, които преди се изпълняваха | `site/dist` + playwright |
| `04-stranici.mjs` | всяка страница се рисува без грешки | `site/dist` + playwright |
| `05-sadarzhanie.mjs` | конспект, разбор при грешен отговор, всички полета на казуса | `site/dist` + playwright |
| `06-sesii.mjs` | второ влизане изхвърля първото; чужда сесия не се пипа | сървър + база |
| `07-ustrojstva-brauzar.mjs` | изхвърленият вижда обяснение; потвърждение на устройство; лентите | сървър + база + `site/dist` + playwright |
| `08-ustrojstva-i-signali.mjs` | месечен лимит, потвърждение по имейл, теглене на едро, невъзможно движение, прогресивната реакция | сървър + база |

Всеки връща 0 при успех, 1 при провал, 2 когато липсва предпоставка.

| Променлива | По подразбиране |

Администраторският токен се издава от базата — не е нужно да се знае ничия
парола и нищо не се записва на диска.

## Важното за `03-xss.mjs`

Тестът е валидиран срещу счупения код. Ако се върне старата `escapeHtml`
(без екраниране на `'`) и старата форма за нова парола, три от седемте падат:

```
❌ reset-password: излизане от JS низа — ЧУЖДИЯТ КОД СЕ ИЗПЪЛНИ
❌ reset-password: излизане от атрибута — кодът е внедрен в form[onsubmit]
❌ reset-password: класически таг — кодът е внедрен в form[onsubmit]
```

Тест, който свети зелено и върху счупеното, не доказва нищо. Този доказва.

Проверката има два независими критерия: дали чуждият код се е **изпълнил**
(формата се изпраща, бутоните се кликат), и дали изобщо е **внедрен** в
атрибут на страницата. Второто хваща и случаите, в които не сме успели да го
задействаме, но кодът вече е излязъл от данните.

## `05-sadarzhanie.mjs` — учебното съдържание

Проверява трите неща, които студентът реално вижда:

1. **Конспектът** е новият текст, разделен на секции с открояващи се подзаглавия.
2. **Тестът** при грешен отговор показва четири неща: твоят отговор, защо е
   грешен, кой е верният и защо е верен. Останалите грешни опции стоят свити.
3. **Казусът** показва всички полета от учебния формат — подтема, ниво,
   ключови понятия, учебни цели, факти, въпроси, насоки (свити), примерен
   отговор, кратък извод и често срещани грешки.

Влиза през самата форма за вход с тестов акаунт, тоест минава по истинския
път на приложението, а не заобиколно през localStorage.

Изисква тестов студент с достъп до предмета. Ако липсва, проверката се
пропуска с код 2. Създаване:

```sql
INSERT INTO users (email, password_hash, name, role, is_active)
VALUES ('ui-proba@lawplus.test', '<bcrypt хеш>', 'Проба UI', 'student', true);
INSERT INTO purchases (user_id, package_id, amount, status)
VALUES ('<id>', 'oblp', 0, 'completed');
```

Снимки от изпълнението се пишат в `$SNIMKI_DIR` (по подразбиране временната
папка) — полезни са, когато проверка падне.
