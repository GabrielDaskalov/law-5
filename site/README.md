# Law+ — фронтенд

Това е **същият сайт** — същият дизайн, същите екрани, същите функции.
Различното е къде живее кодът и откъде идват данните.

---

## 1. Какво беше и какво е сега

| | преди | сега |
|---|---|---|
| файлове | 1 файл, 13 MB | 58 модула + CSS + `index.html` |
| сглобяване | няма | Vite (хеширани файлове, source maps, минификация) |
| първо зареждане | **13 MB** | **469 KB** (95 KB компресиран JS) |
| учебно съдържание | вградено в страницата | в базата, тегли се при нужда |
| заключване на платеното | в браузъра, върху вече свалени данни | на сървъра, преди данните да тръгнат |
| верни отговори на тестове | пътуват заедно с въпроса | отделна заявка след отговора |
| редакция на съдържание | в localStorage на един браузър | в базата, вижда се от всички |

Дизайнът е проверен пиксел по пиксел: снимки на 10 публични екрана преди и
след — идентични (единственото разминаване е броячът „247 студенти учат в
момента“, който е случаен по замисъл).

## 2. Как е разделен монолитът

`app.js` беше 9 250 реда с ясни секционни коментари. Разделянето е по тях, с
инструмент, не на ръка:

* всяка секция → отделен модул в `src/parts/`;
* `export` за обявените имена и `import` за чуждите — генерирани чрез
  разбор на кода (`acorn`), а не с търсене по текст;
* `src/main.js` внася модулите **в реда, в който бяха**, защото част от тях
  се изпълняват при зареждане (тема, рутер, клавишни комбинации).

Едно име (`toggleTheme`) беше обявено два пъти; по-късното засенчваше
по-ранното. По-ранното е преименувано на `toggleThemeLegacyUnused` и е
оставено за справка — поведението е същото, но вече няма два еднакви символа.

### Мостът към глобалната област

26 функции се викат от `onclick="..."` в шаблоните. Такива атрибути се
изпълняват в глобалната област, а модулите имат своя. Затова накрая на
`main.js` точно тези 26 — и само те — се закачат на `window`, с коментар.
Когато шаблоните минат на `addEventListener`, блокът отпада изцяло.

### `window.PA_DATA`

Около 40 места четат `PA_DATA.<нещо>[предмет]`. Вместо да се пренапишат
всичките наведнъж (тоест да се пипнат почти всички екрани), `PA_DATA` е
запазено като име, но е `Proxy` към кеша от сървъра — `src/lib/padata-bridge.js`.
Нищо не съществува в него, преди сървърът да го е дал, а той дава само това,
за което потребителят има право.

Това е преходно. Когато екраните минат директно към `ContentStore`, файлът
се изтрива и нищо друго не се променя.

## 3. Откъде идват данните

```
екран  →  ContentStore.quiz(id)   (синхронно, както винаги)
             ↓
          src/lib/content.js      (кеш в паметта)
             ↑
          рутерът вика prepareRoute() ПРЕДИ да рисува
             ↓
          GET /api/content/...    (сървърът проверява достъпа)
```

**`src/lib/prepare.js`** казва какво трябва да е свалено за всеки маршрут.
Показва скелет, тегли, чак тогава пуска екрана. Затова нито един екран не е
пренаписан на асинхронен.

Внимание при промени: `prepareRoute` трябва да зарежда **същата** тема,
която екранът ще покаже. Параметърът е `?chapter=`, а при липса се пада на
последно четената тема — логиката е дублирана в `activeChapterIndex()` и в
`renderConspect()`. Ако се разминат, ще се тегли един конспект, а ще се
показва друг.

## 4. Какво пази плащането

1. **Никакво платено съдържание не е в бъндъла.** Проверено: търсене за
   `суброгация`, `чл. 79 ЗЗД`, `Неустойката е предварително` в сглобения
   JS → нула попадения.
2. **Всяка заявка минава през `user_has_subject`** на сървъра. Първите
   `free_topic_limit` теми са отворени за витрина.
3. **Верният отговор не идва с въпроса.** `GET /content/quiz` съзнателно не
   селектира `correct_index`, `answer`, `accept`, `explanation`. Проверката е
   `POST /content/quiz/:id/check`.
4. **Примерното решение на казус** се тегли отделно, при натискане на бутона.

## 5. Пускане

```bash
npm install
npm run dev      # http://localhost:5173, /api се препраща към localhost:3000
npm run build    # → dist/
```

`dist/` се сервира статично. `nginx` препраща `/api` и `/health` към Node —
примерна конфигурация в `deploy/nginx.conf.example`.

За бърза локална проверка без nginx:

```bash
node serve.mjs dist        # сайтът на 8080, /api → localhost:3000
```

## 7. Какво остава

Честно, за да не се търси:

1. **Модулите носят стария стил на кода** — глобални функции, шаблонни
   низове, `innerHTML`. Разделянето нарочно не пипна съдържанието на
   функциите; целта беше да няма промяна в поведението. Постепенното
   почистване е следваща стъпка, вече по един файл.
2. **Няма типове.** Проектът е чист JavaScript. `jsconfig.json` +
   `// @ts-check` по файлове е евтин начин да се започне.
3. **`onclick` в шаблоните.** Работят през моста към `window`. Минаването
   към `addEventListener` е механично, но пипа много шаблони.
4. **Разделяне на чънкове** — извадени са само админският панел и правните
   текстове (те са едри и рядко се отварят). Може и повече.
5. **AI асистентът** чете съдържание през `PA_DATA` моста — тоест вижда само
   свалените материали. Ако трябва да работи върху целия предмет, иска
   собствен маршрут на сървъра.
6. ~~**`middleware/auth.ts` в backend-а пада „отворено“** при срив на
   базата.~~ **Поправено** при одита по сигурността — сега при недостъпна
   база заявката се отказва. Виж `промени/` в корена на пакета.
