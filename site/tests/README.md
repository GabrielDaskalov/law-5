# Проверки през браузър

Минават през истински браузър и правят това, което прави студентът — не са
unit тестове.

> Основната, по-нова проверка е в **`backend/scripts/proverka/`** и се пуска
> с една команда (`node backend/scripts/proverka/pusni-vsichko.mjs`). Тези тук
> покриват неща, които тя не покрива: 13-те интерактивни функции, админския
> панел през интерфейса, поведението при спрян сървър и снимките за сравнение.

## Какво проверява всяка

| файл | какво | иска акаунт |
|---|---|---|
| `01-obikolka.mjs` | всичките екрани се отварят; заключеното е заключено; въпросът не носи отговор; проверката минава през сървъра | студент |
| `02-funkcionalno.mjs` | тест до края с резултат; въпроси по избрана задна тема; търсене; флашкарти; сесия след презареждане; изход | студент |
| `03-admin.mjs` | ролята се разпознава; панелът чете от базата; редакция се записва и оставя следа в журнала | администратор |
| `04-bez-survar.mjs` | при спрян backend витрината пак работи, а платените екрани казват какво не е наред | — |
| `05-vizualno.mjs` | снимки на публичните екрани за сравнение с предишна версия | — |
| `06-funkcii.mjs` | 13-те интерактивни функции: помодоро, изпитен жребий, план, бележки, тетрадка на грешките, SRS, постижения, AI асистент, Cmd+K, тема, настройки, поддръжка, отбелязване на тема | студент |

## Какво е нужно

1. **Backend на 3000** и база с внесено съдържание.
2. **Сглобен сайт, сервиран заедно с `/api`:**

```bash
npm run build
node serve.mjs dist            # http://localhost:8080 → API http://localhost:3000
```

3. **Акаунти.** Проверките ги четат от средата — нищо не се пази в кода:

```bash
# студент с купено Облигационно право
export LAWPLUS_TEST_EMAIL=proba@lawplus.test
export LAWPLUS_TEST_PASS=...

# администратор (създава се с: node backend/scripts/zadaj-admin.mjs <имейл> <парола>)
export LAWPLUS_TEST_ADMIN_EMAIL=admin@lawplus.test
export LAWPLUS_TEST_ADMIN_PASS=...
```

Липсва ли някой от тях, проверката спира с изречение какво да се зададе,
вместо да гърми на непонятно място.

## Пускане

```bash
node tests/01-obikolka.mjs
node tests/02-funkcionalno.mjs
node tests/03-admin.mjs
node tests/06-funkcii.mjs

# без backend (друг порт, мъртво API нарочно)
PORT=8081 API_TARGET=http://localhost:9999 node serve.mjs dist &
node tests/04-bez-survar.mjs

# снимки за сравнение
node tests/05-vizualno.mjs http://localhost:8080 ./izhod/vizualno
```

## Две неща за акаунтите

**Месечният лимит на устройствата** важи и за проверките: всяко пускане
тръгва с празно хранилище, тоест изглежда като ново устройство. След няколко
пускания акаунтът опира в лимита и входът иска потвърждение по имейл. За
тестов акаунт лимитът се вдига:

```sql
UPDATE users SET max_devices_30d = 20, max_sessions = 5
 WHERE email = 'proba@lawplus.test';
```

**Едновременните сесии** са 1 по подразбиране — две проверки, пуснати
успоредно с един акаунт, се изхвърлят взаимно. Или се пускат една след друга,
или `max_sessions` се вдига както горе.

## Къде отиват снимките

В `tests/izhod/<име на проверката>/`. Друга папка се задава с
`PROVERKI_IZHOD`. Браузърът се търси автоматично; `CHROME_PATH` го задава
изрично.
