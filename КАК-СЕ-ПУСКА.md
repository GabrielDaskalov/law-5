# Как се пуска от нулата

Пакетът е пълен: backend, фронтенд и учебното съдържание. Няма какво да се
слива на ръка — поправките вече са приложени в `backend/`.

```
lawplus/
  backend/    целият backend (Node + TypeScript + PostgreSQL), с приложените поправки
  site/       целият фронтенд (Vite), със същия дизайн и функции
  content/    учебното съдържание, извлечено от стария монолит + скрипт за внос
  промени/    бележки какво точно е пипано в backend-а и защо
```

---

## 1. База

Нужен е PostgreSQL 16 (или по-нов).

```bash
createdb lawplus

# основната схема
psql lawplus -f backend/src/db/schema.sql

# новият модел на съдържанието (конспекти, тестове, казуси, права за достъп)
psql lawplus -f backend/migrations/010_content_model.sql

# таблиците, които кодът ползваше, но никой не беше създал
# (одитна следа, API ключове, webhooks, предпочитания, заключване на акаунт)
psql lawplus -f backend/src/db/migrations/011_lipsvashti_tablici.sql

# сесии и устройства — един акаунт работи на едно устройство наведнъж
psql lawplus -f backend/src/db/migrations/012_sesii.sql

# регистър на устройствата (месечен лимит) и следа от подозрителното
psql lawplus -f backend/src/db/migrations/013_ustrojstva_i_signali.sql
```

Двете последни са с `IF NOT EXISTS` и могат да се пуснат повторно безопасно.

---

## 2. Backend

```bash
cd backend
cp .env.example .env        # попълни DB_*, JWT_SECRET, STRIPE_* 
npm install
npm run dev                 # разработка, на порт 3000
# или
npm run build && npm start  # production
```

**Задължително преди пускане на живо:** смени `JWT_SECRET`. По подразбиране е
`change-me-in-production` — с него всеки може да си издаде админски токен.

---

## 3. Учебното съдържание

```bash
cd backend
npx ts-node scripts/import-content.ts --dry-run   # първо на сухо
npx ts-node scripts/import-content.ts
```

Скриптът чете от `content/data/` и е идемпотентен — повторно пускане обновява,
не дублира. Има и `--only <код>` за една дисциплина.

Очаквано след внос: 11 предмета, 512 теми, 511 конспекта, 2 627 флашкарти,
4 609 тестови въпроса, 696 казуса. От тях Облигационно право е презаредено с
новия материал: 78 теми, 77 конспекта, 780 въпроса, 156 казуса.

---

## 4. Администратор

```bash
cd backend
node scripts/zadaj-admin.mjs твоя@имейл.bg <парола>
```

Вдига акаунта до администратор или го създава, ако го няма. Паролата се подава
като аргумент нарочно, за да не стои в кода. Смяната обезсилва всички стари
сесии на този акаунт.

---

## 5. Тестов акаунт за проверките

Проверките в `site/tests/` искат акаунт с купено Облигационно право. Две неща,
които иначе изглеждат като дефект:

**Месечният лимит на устройствата** важи и за тях: всяко пускане тръгва с
празно хранилище, тоест изглежда като ново устройство. След няколко пускания
входът започва да иска потвърждение по имейл. За тестов акаунт лимитът се
вдига:

```sql
UPDATE users SET max_devices_30d = 20, max_sessions = 5
 WHERE email = 'proba@lawplus.test';
```

**Едновременните сесии** са 1 по подразбиране — две проверки, пуснати
успоредно с един акаунт, се изхвърлят взаимно.

Подробностите са в `site/tests/README.md`.

## 6. Фронтенд

```bash
cd site
npm install
npm run dev      # разработка на 5173; /api се препраща към localhost:3000
npm run build    # → site/dist/, сервира се статично
```

`nginx` препраща `/api` и `/health` към Node — примерна конфигурация в
`site/deploy/nginx.conf.example`.

## 7. Проверките

Искат **работеща база с внесено съдържание** и акаунтите от т. 4 и 5. Ако се
пуснат на празна база, ще паднат — и това няма да е проблем в кода.

### Всичко наведнъж

```bash
node backend/scripts/proverka/pusni-vsichko.mjs
```

144 проверки: маршрути, съдържание, XSS в истински браузър, страници, сесии,
устройства и сигурност. Иска пуснат сървър, база и сглобен сайт (`site/dist`).

Редът е важен и е зашит в скрипта: проверката за сигурност нарочно изчерпва
лимита на опитите за вход, затова върви последна.

### Unit тестове

```bash
cd backend && npx jest        # 104 теста
```

### Проверки на достъпа и на админското API

```bash
cd backend
npx ts-node tests/paywall.test-harness.ts          # 10 проверки на достъпа
npx ts-node tests/admin-content.test-harness.ts    # 37 проверки на админското API
```

### Проверки през браузър (интерактивните функции, админският панел)

```bash
cd site
npm run build
node serve.mjs dist                 # сайтът на 8080, /api → localhost:3000

export LAWPLUS_TEST_EMAIL=proba@lawplus.test
export LAWPLUS_TEST_PASS=...
export LAWPLUS_TEST_ADMIN_EMAIL=admin@lawplus.test
export LAWPLUS_TEST_ADMIN_PASS=...

node tests/01-obikolka.mjs      # екраните и правилата за достъп
node tests/02-funkcionalno.mjs  # тест до края, търсене, сесия
node tests/03-admin.mjs         # админ панел срещу базата
node tests/06-funkcii.mjs       # 13-те интерактивни функции
```

Браузърът се търси автоматично (`CHROME_PATH` го задава изрично). Снимките
отиват в `site/tests/izhod/`. Подробностите са в `site/tests/README.md`.

## 8. Какво НЕ е включено

* `.env` с истински стойности (само `.env.example`).
* `node_modules` — идват от `npm install`.
* Ключове за Stripe, SMTP и домейн.
* Данните от текущата продукция, ако има такива.
